## キャラ制作と動画制作の担当範囲

| プロジェクト | 管理・制作するもの |
| --- | --- |
| `knowledge-anime-character-system` | 謎生物の設定・造形、原画、ベクター清書、パーツ分け、表情・ポーズ差分、正式キャラ素材の承認と版管理 |
| `character-video-studio` | 台本・入力JSON、背景と画面レイアウト、採用済み素材の配置、字幕、音声、動画内の演出・合成、Remotionの再利用構造、MP4出力、動画の出典・使用素材記録 |

このSkillは動画制作のためのもの。動画の作業中にキャラの描き直し、トレース、体形・小物・設定の変更、新しい表情・ポーズ素材の制作を始めない。キャラ制作が必要なら、その内容をキャラ制作プロジェクトの別作業として扱う。

動画側で行う拡縮・配置・表示切替・既存パーツの動きは、採用済み素材を使った非破壊の演出に留める。必要な表情やパーツが不足した場合は、不足を記録し、キャラ素材の制作・確定とは分けて動画側で進められる工程を進める。仮素材を使った確認は正式キャラ素材の承認と区別する。

設定画像は動画の雰囲気・配色を理解する参考資料として読み、動画側から正本を編集しない。使用版をコピーして固定し、正本の更新時にも既存動画の素材を自動で差し替えない。キャラ素材の完成・承認と、動画の完成・検証は別々に報告する。

## 素材に合わせてSkillを育てる方針

Skillは素材の特徴と用途に合わせて作成・更新する。汎用の作例のデザインをそのまま当てはめず、実際の採用素材を確認して制作方針を決める。

- キャラ制作Skillは、謎生物の造形・意匠を保ちながら清書やパーツ制作を行うためのもの。キャラ制作プロジェクトで管理する。
- 動画制作Skillは、採用済み素材に合う背景・レイアウト・動き・音声を設計するためのもの。動画制作プロジェクトで管理する。
- 共通の制作手順と再利用の原則はSkill本体に残す。素材固有の注意点・参照画像・検証結果は必要に応じて参照資料へまとめ、本文から参照できるようにする。
- 動画ごとの台本・画像・音声はJSONと素材ファイルで差し替える。題材が変わるたびにSkillやReactコンポーネントを書き換える運用にしない。
- 新しい素材で確認できた制約や改善点がある場合に、その担当範囲のSkillを更新する。素材の追加を理由にキャラ制作と動画制作の担当範囲を混ぜない。

## 依頼範囲に合わせる

環境・Skillの整備だけを依頼された段階では、台本、仮音声、試作動画を作らない。構成のみの依頼なら構成まで、動画制作の依頼なら必要な編集と検証まで進める。公開・投稿は依頼された場合に行う。

## 記事から構成へ

1. 記事の結論・対象・日付と、動画で伝える主張を確認する。主張・数値ごとにURLや該当箇所を出典ファイルへ記録する。原文の事実と制作側の解釈を区別する。
2. 1本1テーマ・1つの結論を基本に、冒頭の疑問、説明、具体例、結論へ整理する。初回の目安は30秒だが、ユーザーの尺指定と音声を優先する。
3. `RankingScene` は番号付き説明にも使える。ランキングを無理に作らない。事実として順位を示す場合は評価基準・対象・集計期間を出典へ記録する。
4. 字幕は画面で読める短い文にし、読み上げ文と必要に応じて分ける。原文を短くする際も条件・単位・日付を落として意味を変えない。

## キャラ・素材

- 3キャラはオリジナルの「謎生物」。耳や体形からウサギ・鳥などの動物種に分類したり、人間として扱ったりしない。説明・発見・分析は動画内の役割であり、種族や人間の職業を新しく設定するものではない。原画の形・小物・表情と、好奇心や親しみやすさを保つ。
- ルーノ：説明・案内。ミーノ：疑問・発見。カーノ：分析・整理。最初から3人全員を登場させる必要はない。
- 正本はプロジェクトルートから `../knowledge-anime-character-system/`。採用された素材のコピーを `public/assets/` に置く。原画を改変・再生成して正式素材に置き換えない。
- 使用素材の参照元・版・SHA-256・承認状態を `public/assets/manifest.json` に記録する。未承認の清書案は正式素材として扱わない。
- 音声・BGMは `public/audio/` に置き、提供元・利用条件・クレジットを出典へ記録する。音声を使う場合は実ファイルの尺・読み・間にシーンを合わせる。

## キャラに合わせた背景・デザイン

- 標準の方向は `19_10_09` の白を基調とした広い余白と淡い青の世界観。`03_43_18` の淡いクリーム、木の机、本棚、植物の温かさも参照し、学び・発見・探検を感じる空間にする。
- 背景色は白〜淡いクリーム。地図、遠景の建物、雲、航路の点線は薄い青で控えめに置く。本・地球儀・羅針盤・植物などを必要な場面に添える。すべてのモチーフを毎カット詰め込まず、キャラ・字幕・紹介画像のための余白を優先する。
- 背景の世界地図や建物は雰囲気づくりの装飾。説明に使う地図・図表・数値は別レイヤーに置き、正確な資料から作る。
- 文字・主要な線は濃紺を基本にする。ルーノの青、ミーノの温かいオレンジ、カーノの淡い水色・青緑、羅針盤や本の金色をアクセントにする。オレンジは全面背景ではなく、発見や驚きの小さな強調に使う。
- 初期配色の仮値は、白 `#FFFFFF`、クリーム `#FFF9EF`、濃紺 `#122B55`、淡青 `#DEEDF7`、オレンジ `#F2B56B`、青緑 `#87BDB7`、金 `#C9A45C`。原画から厳密に抽出した確定色ではなく、実際のキャラ素材を置いて調整する。
- 見出しは読みやすく大きく、本文はスマートフォンで読める太さと文字量にする。記事の赤黒グラデーション・極太の縁取り・蛍光色のコメント枠は標準に採用しない。コメントは明るい面に濃紺の文字を置き、キャラのアクセント色で話者を示す。
- 記事のオレンジ放射背景や常時回転は標準に採用しない。背景は基本静止。場面の切替や発見の瞬間には、小さな進入・短い反応・控えめな強調を使う。大きなズーム反動や常時揺れる文字で、謎生物の表情や小物を埋もれさせない。
- 参考画像は雰囲気・配色・配置の資料。設定図全体や画像内の説明文を背景としてそのまま貼らず、背景、キャラ、紹介画像、文字を独立した要素として実装する。
- 同じ背景・文字・コメント・動きの設計を次の動画でも使う。題材の変更はJSON・画像・音声の差し替えで行い、動画ごとにReactコンポーネントを書き換える構造にしない。

## Remotionへの反映

`video.json` を編集するときは現在のスキーマを確認する。標準構成は1080×1920、30fps。シーンの秒数から尺を計算し、データを変えるたびに尺を手動で重複管理しない。

- 冒頭：`src/components/Intro.tsx`
- 番号付き説明：`src/components/RankingScene.tsx`
- コメント・立ち絵：`src/components/CommentBox.tsx`
- 締め：`src/components/Ending.tsx`

既存の任意項目 `characterAsset`、`narration` は `public/` からの相対パスを使う。新しい項目が必要ならスキーマと表示側を一緒に変更する。演出はRemotionのフレームから計算し、通常のタイマーや未固定の乱数を使わない。

重要な文字・数字・顔は右端・下端に寄せない。実際の投稿UIとスマートフォン表示で確認し、必要に応じて余白・文字量・文字サイズを調整する。

## 検証・成果物

コードやデータを編集した場合は `npm run check`。動画を制作する場合は `npm run dev` でプレビューし、変更したカットの静止画と最終動画を確認する。

キャラ素材が未完成の段階で試験動画の制作を依頼された場合は、試験用JSONと `TestRanking3` / `TestCollection5` を使える。`testMode: true` で名前・配置枠と試験注記を表示する。正式素材の代わりにキャラを再生成しない。`npm run preview:test` と `npm run render:test` の使い方は [../../README.md](../../README.md) を参照する。試験用の文字量で確認した結果を、正式キャラ・別の台本・音声の検証へ広げない。

```sh
npm run check
npm run dev
npm run still
npm run render
```

`still` の既定フレーム210は現在の対象カットに応じて変更できる。任意フレームの例：

```sh
npx remotion still src/index.ts Shorts output/preview.png --frame=90
```

動画は `output/short.mp4` に書き出す。空ファイルを成果物として置かない。字幕の欠け、図解・数値、素材の形、音声同期を確認し、実行していない検証は未確認と報告する。完成報告には変更点、成果物、実施した確認、残る作業を含める。
