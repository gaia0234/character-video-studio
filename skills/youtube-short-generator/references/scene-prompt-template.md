# 場景プロンプト・テンプレート

2026-10-30作成。ロング解説の1場景をRemotionで実装するときの指示テンプレート。AI動画生成モデルへ渡すプロンプトではなく、実装担当・OC・PMの間で、画面・動き・字幕・音声の意図を共有するためのもの。

動きの基準は [motion-design.md](motion-design.md) を先に読む。場景は `src/data/longform/` の対象版JSONと、`src/longform/` の既存コンポーネントを基準にする。

## 使い方

1. 1場景1目的で書く。複数の論点を1場景へ詰めない。
2. 事実・数値・出典は台本正本から取る。このテンプレートで新しい事実を補わない。
3. 既存の背景・人物・図・字幕UIを再利用する。新規資産は不足分だけにする。
4. 場景単独のstillまたはMP4で確認する。全編レンダーは本人の明示指示まで行わない。
5. 実装後は、このテンプレートの「受入」項目と [motion-design.md](motion-design.md) の確認項目を照合する。

## 記入例（架空の場景）

以下は書き方の例。数値・企業名・出来事は実際の主張ではない。

```text
Scene ID: S00-01
対象版: 対象版recordで固定
目的: 展示会場で、エンジンとモーターという2種類の動力があることを理解する
尺: 6.0秒
ナレーション: 台本IDに従う。1文。
字幕: 1行。動きが止まってから表示。

背景:
  種類: 展示会場
  レイヤー: 奥に窓と来場者、中に展示台、手前に人物
  既存資産または新規: 新規SVG背景（既存の紙ボードとは別）
  色・線幅: ベージュ基調、濃紺の線、青と赤のアクセント

人物:
  誰が: 技術者風の人物2人
  位置: 左右の手前
  既存素材 / 不足ポーズ: 既存素材。指差しポーズが不足なら新規
  動き: 右の人物が展示台を指差す。左の人物は小さくうなずく

オブジェクト:
  何を: エンジンとモーターの模式図
  既存コンポーネント: ToyotaTHSCutaway を参考
  出現方法: エンジン→モーターの順にpop。最後に接続線
  ラベル: 「エンジン」「モーター」の2つ
  注記: 模式図であることを小さく表示

カメラ:
  開始と終了: 100% → 106%
  中心座標: 展示台
  移動時間: 1.0秒
  字幕・章バッジとの干渉: なし

モーション順:
  0.0-0.4: 背景と人物を表示
  0.4-1.0: カメラをプッシュイン、右の人物が指差す
  1.0-1.6: エンジン出現
  1.6-2.2: モーター出現、接続線
  2.2-3.0: ラベル2つをstagger表示
  保持: 3.0-5.0 字幕を読ませる。動きを止める
  転換: 5.0でカット

音声:
  開始offset: 0.2秒
  効果音: 出現時に小さく1回まで
  BGM: 権利確認済みのもの
  実尺確認: WAVの実尺と場景秒を照合

禁止:
  字幕と重なる動き: なし
  常時回転・常時揺れ: なし
  事実にない数値・ラベル: 追加しない
  参考動画のコピー: 背景・人物・ラベルをそのまま使わない

受入:
  代表フレーム（0.2秒間隔）: 30枚程度
  文字切れ: なし
  字幕干渉: なし
  人物見切れ: なし
  色コントラスト: ラベルが読める
  再レンダー再現: 同一フレーム
  PM/本人受入: 別途
```

## Remotionへの対応

- 場景JSONの `sceneID`、字幕、音声、秒数は対象版の既存スキーマに合わせる。新規フィールドが必要なら、スキーマと表示側を同じ変更で追加する。
- 背景・人物・図は `AbsoluteFill` のレイヤーとして分ける。1枚の画像に合成しない。
- カメラは背景・人物・図をまとめた親に `transform` を掛ける。字幕・章バッジはカメラの外に置く。
- 出現は `spring`、移動は `interpolate`、順序は `Sequence` または `frame` の範囲で制御する。
- ラベルのstaggerは配列のindexから計算する。`Math.random()` を使わない。
- 既存の `ToyotaV3Chart.tsx`、`ToyotaTHSCutaway.tsx`、`ToyotaHybridDriving.tsx`、`ToyotaPriusRegeneration.tsx` を優先する。
- 字幕・章UI・年バッジは `LongformToyota01V11.tsx` の既存配置を基準にする。

## 委譲時の指示

OCや実装担当へ渡すときは、次を明記する。

- 対象repo・branch・HEAD、所有ファイル、対象場景ID。
- 参照する台本・事実資料・対象版record。
- 既存資産と新規資産の区別。新規に作るファイル名。
- 出力範囲（still / 場景MP4 / 全編禁止）。
- 完了条件（型検査、代表フレーム、字幕干渉、再レンダー再現）。
- 禁止（新規ツール、外部AI生成、全編レンダー、公開、無断の素材変更）。
- 失敗累計と停止条件。

## よくある失敗

- AI動画生成のプロンプト（カメラ・照明・被写体）を書いてしまい、場景の情報設計がない。
- 1場景に動きを詰め込み、字幕を読む時間がない。
- ラベルが対象から離れ、どの部品の名前か分からない。
- 背景・人物・図を1枚の画像に合成し、個別に動かせない。
- 事実資料にない数値・年号・企業名を、画面の都合で足す。
- 参考動画の構図・キャラ・テロップをそのままコピーする。
- 代表フレームだけ見て、連続再生の速さ・間を確認しない。
- 場景単独の合格を、全編・音声・本人受入の合格として報告する。

## 受入チェック

- [ ] 場景の目的が一つに絞られている。
- [ ] 字幕・章バッジ・年バッジと動きが干渉しない。
- [ ] 主要な動きが同時に複数ない。
- [ ] 文字・ラベルを出した後の保持時間がある。
- [ ] 数値・年号・単位が台本正本と一致する。
- [ ] 既存資産を再利用し、新規資産は不足分だけ。
- [ ] 0.2秒間隔の代表フレームで文字切れ・見切れがない。
- [ ] 再レンダーで同じ動きになる。
- [ ] 場景単独の出力である。全編レンダーをしていない。
- [ ] 未確認（連続再生、聴感、本人受入）を区別して報告する。
